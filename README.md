# Pre-Manufacturing Digital Twin (PMDT) for Solar Electric Vehicles

Reference code accompanying the paper *"A Pre-Manufacturing Digital Twin for
Solar Electric Vehicles: Coupling a Physics-Based Plant Simulator with
Recurrent Neural Networks."*

The PMDT is a **simulation-based, pre-manufacturing** digital-twin framework:
it mirrors a vehicle **design** before any physical unit exists, using a
physics simulator as the sole source of ground truth. It is **not** a
deployment-stage digital twin synchronized against telemetry from a real
hardware asset, and no result here should be read as hardware-validated.

## 2. Contributions mapped to code

### (1) Recurrent prognostics across five design tiers — Section 3 of the main file
- Two-tier stacked LSTM/GRU (`PrognosticRNN`) predicting `SoH_Proxy` and
  `Remaining_Range_km` over 20-step windows (`PROG_SEQ_LEN`), evaluated on
  three named tiers (`interpolation`, `combination_shift`, `extrapolation`;
  the latter two out-of-distribution) plus train/val tiers = five design tiers.
- Deterministic **persistence** and **linear-regression** baselines
  (`run_rnn_baselines`), merged into one formal comparison table
  (`build_rnn_formal_comparison_table`).
- **Multi-seed statistics** (mean/std/worst-case over 3 seeds,
  `run_prognostics_pipeline_multiseed`) and **paired significance tests**
  (`run_prognostics_significance_tests`: paired t-test LSTM vs GRU, one-sample
  t-tests of each model vs persistence).
- **Horizon sweep** (`run_horizon_sweep`): fixed input window, target shifted
  10/30/60/120/300 s ahead — reproducing the finding that recurrent models
  trail persistence at short horizons but overtake it by 120–300 s. Output:
  `horizon_sweep_full.csv`.

> Note: `SoH_Proxy` is a **synthetic, simulator-derived** quantity (a function
> of cumulative Ah-throughput and thermal stress), not a measured battery
> State-of-Health signal.

### (2) Voltage synchronization via physics-residual prediction — Section 5
- Instead of regressing raw voltage, the module computes an analytic
  equivalent-circuit estimate using the same zeroth-order model as the plant
  simulator,
  `V_physics(t) = OCV(SoC(t)) − I(t)·R_int` (`battery_ocv`),
  and trains a small LSTM (`VoltageLSTM`) to predict only the residual
  `ΔV(t) = V_true(t) − V_physics(t)`.
- Evaluated against **five variants** on identical held-out temporal test
  segments: `persistence`, `physics_only`, `kalman_filter`, `nohist`
  (ablation: no voltage history), and `full` — with multi-seed reporting
  (`run_sync_pipeline_multiseed`). Strict per-config temporal split
  (70/15/15) prevents leakage.

### (3) Closed-loop reliability gate + automated correction — Section 6
- Reliability gates (`MC_THRESHOLDS`): final SoH ≥ 99.60 %, range ≥ 280 km,
  max speed-tracking error ≤ 1.0 km/h, battery temperature within 15–35 °C.
- Fleet-wide gate evaluation with Wilson 95 % CIs on pass rates
  (`mc_evaluate_fleet_gates`, `mc_wilson_ci`).
- Iterative capacity-search correction (`mc_local_capacity_search`,
  `mc_run_correction_on_all_failures`) re-simulating corrected designs until
  they pass; results in `closed_loop_correction_results.csv`.
- Optional mass-coupling sensitivity analysis
  (`mc_run_mass_coupling_sensitivity`).

> Naming note: the `monte_carlo` CLI subcommand / `mc_*` prefix are kept for
> backward compatibility, but this stage is a deterministic **design-space
> reliability analysis** over sampled fleet designs — not stochastic Monte
> Carlo uncertainty propagation.

### Synthetic fleet — Section 2
`build_fleet` generates a **176-design** fleet (80 train / 16 val / 20
interpolation / 20 combination-shift / 40 extrapolation), each design run
through the plant simulator over a 3000 s drive cycle at dt = 1 s
(seed = 42). Every out-of-envelope design fails the reliability gate before
any hardware exists, and closed-loop correction recovers all failing designs
(median ≈ 2 iterations).

## 4. Usage

Run from the repository root:

```bash
python pmdt_unified_optimized.py all              # full pipeline (default)
python pmdt_unified_optimized.py fleet            # Stage 1: simulate 176-design fleet
python pmdt_unified_optimized.py rnn              # Stage 2: prognostics + baselines + significance tests
python pmdt_unified_optimized.py baselines        # Stage 2b: persistence / linear-regression only
python pmdt_unified_optimized.py sync             # Stage 3: voltage synchronization (incl. Kalman baseline)
python pmdt_unified_optimized.py monte_carlo      # Stage 4: reliability gates + closed-loop correction
```

Options:

```
--t-stop FLOAT   Drive-cycle length in seconds (default 3000.0)
--dt     FLOAT   Simulation time step in seconds (default 1.0)
--n-seeds INT    Seeds for multiseed statistical reporting (default 3)
--skip-sensitivity   Skip the mass-coupling sensitivity analysis
```

Any downstream stage calls `ensure_fleet()` automatically, so you can run
`rnn`, `sync`, or `monte_carlo` directly without first running `fleet` — the
fleet is generated on demand if the CSVs are missing.

Example (quick smoke configuration):

```bash
python pmdt_unified_optimized.py all --t-stop 600 --dt 1 --skip-sensitivity
```

Individual functions are also importable for ad-hoc analysis:

```python
import pmdt_unified_optimized as m
m.run_horizon_sweep()                      # Table VI-style horizon sweep
m.run_sync_pipeline_multiseed(n_seeds=3)   # Table IV-style sync comparison
```

## 6. Reproducibility & determinism

- Global seeds: `torch.manual_seed(42)`, `np.random.seed(42)`; fleet sampling
  uses a dedicated `default_rng(FLEET_SEED=42)`.
- All randomness (env perturbations, splits, weight init) is seed-derived;
  reruns reproduce tables/figures modulo float nondeterminism in BLAS
  reductions.
- Multiseed stages expose `--n-seeds`; significance tests require ≥ 2 seeds.

## 7. Scope caveats (please cite accurately)

1. **Pre-manufacturing only.** The twin validates *designs in simulation*;
   there is no physical SEV and no hardware-in-the-loop claim.
2. **`SoH_Proxy` is synthetic**, derived from simulator state, not measured
   battery cycling data.
3. **"Monte Carlo" stage** is a design-space reliability analysis over a
   deterministic sample of fleet designs (see naming notes in Section 6 of
   the source).
4. The horizon sweep uses a lighter protocol (single seed, 15 epochs) than
   the main 3-seed/25-epoch prognostic runs — a disclosed compute-budget
   choice, documented in the function docstring.

## 8. Code optimization changelog (this branch)

The unified script was refactored for correctness and speed **without
changing physics, training, or statistical logic**:

1. **O(N²) → O(N)** rolling-window range estimator in the plant simulator
   (running totals instead of per-step window sums); numerically equivalent
   to ~1e-6 relative (float32 rounding) precision.
2. Fixed aliased empty DataFrames in `sync_temporal_split_per_config`
   (`train_df is val_df is test_df` previously).
3. Fixed potential `TypeError` in `mc_get_seed` when both `env_seed` and
   `config_id` are absent (falls back to 0).
4. Deduplicated group-by-config/sort-by-Time logic into `_iter_sorted_groups`.
5. Faster batched inference: default batch 8192 → 16384 with
   `ascontiguousarray` materialization of strided window views.
6. Fail-fast NaN guard (`_check_no_nan`) at sequence-construction time.
7. Fixed a hard `SyntaxError` in `main()` (`global` declared after use of
   `T_STOP_DEFAULT` / `DT_DEFAULT`).
8. Split-name-based config selection in the sync stage (removed hardcoded
   `range(0, 48)` that silently broke under the fleet-size change).
